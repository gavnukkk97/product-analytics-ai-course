## Цели

После урока вы:

- **Общий минимум:** заполняете карточку эксперимента Ритма (гипотеза X→Y→Z → primary/guardrail → выборка → окно → стоп → decision rule → что *не* смотрим) и честно читаете исход.
- **Аналитик:** считаете эффект по `users.ab_variant` на полном датасете; проверяете **SRM**; ловите peeking и подгонку сегментов; знаете, зачем CUPED и юнит=user; сверяете логику с ключом преподавателя (не подгоняете ответ).
- **Продакт:** принимаете решение «растим / разворачиваем / убиваем / нет решения» с деньгами; не требуете «ещё сутки, там почти p&lt;0.05»; понимаете, что ~⅓ идей выигрывает — проигрыш теста экономит деньги.

## Теория коротко

### 1. Цикл: 80% судьбы — до запуска

A/B — не «посмотрели дашборд». Конвейер:

```mermaid
flowchart LR
  H[Гипотеза X→Y→Z] --> Card[Карточка / design-doc]
  Card --> Split[Сплит + SRM]
  Split --> Run[Набор N / окно]
  Run --> Read[Чтение primary + guardrails]
  Read --> Dec[Decision rule]
  Dec --> Money[Деньги / раскат]
```

Лишь около **⅓** идей улучшает целевые метрики (индустриальный ориентир). Машина экспериментов в первую очередь **дёшево отстреливает плохие идеи**. «Катим всё без теста» и «тестируем случайно» проигрывают приоритизированному бэклогу при той же мощности платформы.

Карточка: [`visuals/m2-5-experiment-anatomy.svg`](./visuals/m2-5-experiment-anatomy.svg).

### 2. Гипотеза X→Y→Z и одна primary (OEC)

Рабочий фрейм:

| Часть | Вопрос | Пример Ритма |
|---|---|---|
| **X** | что меняем и *почему* сработает | users бросают до aha из‑за раннего paywall; перенос после `streak_3` |
| **Y** | какая метрика сдвинется | habit→subscribe_14d |
| **Z** | зачем бизнесу | больше Pro / LTV при живом depth |

«Переделаем paywall» — не гипотеза. «Поднимем конверсию» — не гипотеза (нет X). Без Z команда оптимизирует кликбейт.

**Primary / OEC** — *одна* метрика решения. Две «главные» = нет критерия при конфликте. Выбор по двум осям:

1. **Близость к деньгам** — драйвер (habit→sub) лучше чистого CTR paywall; выручка на user часто слишком шумная для UI-теста.
2. **Чувствительность** — метрика должна ловиться вашим N при типичном эффекте механики.

**Guardrails** (3–5) — с **порогами до старта**: у нас `d7_depth_ge3`, `early_paywall_share`.  
**Инварианты** — не должны шевелиться от фичи (доля internal, скорость логов, **SRM**): если шевельнулись — сломан пайплайн, не «эффект продукта».

| Поле | Учебный дефолт на Ритме |
|---|---|
| Гипотеза | «Paywall после streak_3 повышает habit→subscribe за 14д и снижает early paywall» |
| Primary | **habit_to_subscribe_14d** |
| Guardrails | **d7_depth_ge3**; **early_paywall_share** |
| Assignment | 50/50 на install, без internal; юнит = **user** |
| Окно | фиксированное от install/habit — не «пока не понравится» |
| Не смотрим | 20 срезов «а вдруг на web»; цвет кнопки как primary |

### 3. Ошибки I/II, мощность, sample size

| Ошибка | Статистика | Бизнес |
|---|---|---|
| I (ложная тревога) | «эффект есть», а шум | раскатили вредный paywall |
| II (пропуск) | «эффекта нет», а он есть | убили полезный рычаг |

Мощность и размер — про цену ошибки II. Формула и ловушка **забытого ×2** — в М2.4. Здесь в карточку: α, мощность, MDE из экономики, N, длительность **целыми неделями**, критерий стопа.

Не сравнивайте наблюдаемый эффект с MDE («почти поймали +2.8 при MDE +3»). MDE — что *проектировали*; что *измерили* — ДИ (М2.4).

### 4. Юнит рандомизации = юнит анализа

На Ритме монету бросают **user** (`users.ab_variant`). Анализ — тоже на users, не на событиях `paywall_view` / чек-инах.

Иначе: много событий одного человека выглядят как «большая выборка», SE занижен, α раздувается — «пустышки» едут в прод. Сессия как юнит «по привычке» даёт одного человека в обеих группах — эффект перетекает. Кластеры (гео и т.п.) — отдельный дизайн; на учебном стенде не нужны.

### 5. SRM и гигиена сплита

**Sample Ratio Mismatch** — факт численности групп уехал от плана (не 50/50). Проверка — согласие долей (хи-квадрат / z). На стенде:

```sql
SELECT ab_variant, COUNT(*) AS n
FROM users
WHERE ab_experiment = 'paywall_timing_2026q3'
  AND is_internal = false
  AND ab_variant IS NOT NULL
GROUP BY 1;
```

Правила курса:

| Правило | Смысл |
|---|---|
| Порог алерта **жёстче**, чем 0,05 (ориентир **0,001**) | чек массовый; 0,05 → alarm fatigue |
| SRM → **стоп**, результатам не верить | смещение любого знака |
| Чинить **причину**, не «докрутить анализ» | асимметричный фильтр создаёт и SRM, и ложный lift |
| Перезапуск с нуля | счётчик N/окна обнуляется |
| Зелёный SRM на малом N ничего не гарантирует | детектор слеп, пока мало users |

Типичные причины: асимметричные фильтры (боты / «без событий»), потеря логов одной ветки, разный старт вариантов, баг хэша. **A/A/B в каждом тесте** «для надёжности» почти всегда вредно: ×1,5 трафика + лишние сравнения. A/A — аудит *платформы*, не ритуал каждого продукта.

На учебном full-стенде доли близки к 50/50; на семпле шум большой — не путайте с прод-SRM.

### 6. Подглядывание, множественные сравнения, сегменты

| Антипаттерн | Почему врёт | Что делать |
|---|---|---|
| Peeking каждый день | α с 5% → 20–30%; ранний «прокрас» завышает эффект | одно окно / alpha-spending / sequential **заранее** |
| «Просто смотрели, не останавливались» | знание p влияет на продление/метрику | фикс-горизонт или честный sequential |
| 15 метрик без поправки | одна «зелёная» случайно (m=20 → ~64% хоть одной ложной тревоги) | одна primary; guardrails с порогами; остальное — описательно |
| Сегмент после факта | p-hacking / forking paths | сегменты в карточке *до* чтения или новый тест |
| Малый семпл стенда | знак эффекта плавает | полный датасет для зачёта P4 |

Честное чтение: [`visuals/m2-5-read-honestly.svg`](./visuals/m2-5-read-honestly.svg).

Sequential (group sequential, mSPRT…) — опция сильным; ядро курса — **фиксированный горизонт**.

### 7. CUPED: меньше шума без смены метрики (обзор)

n ~ σ². **CUPED** вычитает из метрики предсказуемую по *пре-периоду* часть: \(Y_{cv} = Y - \theta X\), где X — та же метрика **до** старта теста. Дисперсия падает примерно на долю \(\rho^2\) (корреляция pre↔post): при ρ=0,6 экономия ~36% наблюдений, при 0,8 — ~64%.

На Ритме для binary habit→sub пре-корреляция скромная; идея важнее формулы. Гигиена:

- ковариата **только до тритмента** (иначе «съедает» эффект);
- θ на объединённых группах;
- новички без истории — отдельно (imputation / без CUPED);
- не заменяет честный дизайн и SRM.

Полный CUPAC / MultiCUPED — опциональное чтение stats-ab М3.5–3.6.

### 8. Как считать на стенде (логика анализа)

1. Когорта: `ab_experiment = 'paywall_timing_2026q3'`, `ab_variant` in (control, treatment), `is_internal = false`.
2. **SRM-чек** численностей до интерпретации lift.
3. Primary: среди users с `habit_created` — доля с `subscribe_started` / первой подпиской в окне 14д (определение из М5.1).
4. Guardrail depth: D7 habit depth ≥3 по словарю.
5. Guardrail early paywall: доля paywall с ранним trigger (users или views — **одна** версия).
6. Разница treatment − control в **п.п.** + 95% ДИ (М2.4).
7. Decision rule + деньги: эффект × размер будущей волны × ARPPU/маржа из М1.3.

Преподаватель сверяет знак/порядок с `true_effects`, не требует посимвольного совпадения на малой выборке.

### 9. Decision rule: растим / разворачиваем / убиваем / нет решения

Пишется **до** данных (иначе рационализация):

| | Guardrails в норме | Guardrail просел |
|---|---|---|
| **Primary значимо ↑** (ДИ без 0, направление нужное) | **растим** | не растить; trade-off / новый тест |
| **Primary значимо ↓** | **разворачиваем** / убиваем | откат + разбор |
| **Primary шум** (0 внутри ДИ) | **нет решения** — не «эффекта нет» | нет решения + вопрос к дизайну |

| Исход на Ритме | Типичное решение |
|---|---|
| Primary ↑, guardrails в норме | **растим** treatment |
| Primary ↑, depth просел | **не растить** |
| Primary шум, early paywall ↓ | **не путать** приятный guardrail с победой |
| Primary ↓ | **разворачиваем** / **убиваем** гипотезу timing |

Политика «нет решения»: один заход углубления (сегменты с поправкой) **или** новый дизайн-док; не «продлим, пока не зазеленеет».

### 10. Валидность коротко + эксперимент как мышца

Чеклист до раскатки: юнит ок; SRM зелёный; окно полное; primary одна; нет асимметричных фильтров после факта; novelty/learning не путаем с устойчивым эффектом; cookie churn на учебных данных не моделируем — в проде помним.

A/B на Ритме — навык с P3: гипотеза из диагностики → карточка → честное чтение. Ищите **aha** (кандидат — depth≥3 / `streak_3`): эксперимент проверяет, не ломаем ли путь к aha ранним paywall. Меньше разметки «на всякий клик», больше событий критического пути (М4.3).

## Разобранный пример: карточка до чтения данных

**Эксперимент:** `paywall_timing_2026q3`  
**Гипотеза (X→Y→Z):** ранний paywall режет путь к streak_3 (X) → перенос после streak_3 ↑ habit→subscribe_14d и ↓ early_paywall (Y) → больше Pro без убийства depth (Z).  
**Primary:** habit_to_subscribe_14d.  
**Guardrails:** d7_depth_ge3 (не хуже control на заранее заданные п.п.); early_paywall_share (ожидаем снижение).  
**MDE (учебно):** +3 п.п. primary; N — по М2.4 с ×2.  
**Стоп:** календарь окончания набора + фиксированное окно 14д после habit; без ежедневного p.  
**Decision rule:** матрица §9.  
**Не смотрим как primary:** CV от install; «красивость» экрана; 10 habit_type срезов.  
**SRM:** доли control/treatment до метрик.  
**Деньги:** если +5 п.п. на базе ~7% habit→sub и 5 400 habit / волну ≈ +270 Pro × смешанный платёж — порядок из листа М1.3.

После расчёта на full-синтетике студент пишет вердикт; преподаватель сверяет с ключом (`winner`, `absolute_lift_pp`).

## Практика

Стенд: [`../stand/README.md`](../stand/). Полные данные: `bash scripts/load_generated.sh 2500 42`. Ключ — только у преподавателя.

### Ядро (оба) — артефакт P4 (дизайн + чтение)

1. Заполните **карточку эксперимента**: X→Y→Z, primary, guardrails с порогами, юнит, α/мощность/MDE/N, окно, стоп, decision rule 2×2, список «не смотрим».
2. Зафиксируйте определения primary/guardrails **ссылкой на словарь М5.1**.
3. Опишите план расчёта (фильтры, дедуп, **SRM**) *до* разбивки по вариантам в интерпретации.
4. На full: SRM → primary и guardrails по control/treatment; Δ в п.п.; N; 95% ДИ (М2.4).
5. Решение по матрице + **одно предложение про деньги**.
6. Список «чего не смотрели» — не пустой.

### Расширение «руки»

- SQL/Python: воспроизводимый расчёт трёх метрик + SRM; exclude internal; дедуп subscribe.
- Sanity: assignment ≈ 50/50; истина варианта — `users.ab_variant`, не props события.
- Симуляция peeking: на подвыборке 10% users / раннем срезе по времени — другой знак или «ложный» прокрас.
- (Опция) Набросать CUPED-логику: pre-метрика depth/чекины *до* условного старта vs raw Δ — даже если на binary выигрыш мал, зафиксируйте ρ и вывод «помогло / нет».

### Расширение «решение»

- Бриф защиты 5–10 мин (заготовка М6.1): гипотеза → дизайн → SRM → результат → деньги → риски.
- Политика стопа: что запрещено в чате («ещё денёк, почти значимо»).
- Если primary в шуме, но early paywall сильно упал — какое решение и почему не «частичная победа».
- Одна фраза: что делает команда при SRM-алерте.

## Критерии приёмки

- [ ] Карточка полная: X→Y→Z, одна primary, guardrails с порогами, decision rule, «не смотрим».
- [ ] Есть SRM-чек (или явная оговорка N/мощности детектора на семпле).
- [ ] Расчёт на данных с фильтрами; N, п.п., ДИ.
- [ ] Решение + деньги; ядро + одно расширение.
- [ ] Нет подгонки под ключ; AI не «угадывает winner» без вашего SQL.
